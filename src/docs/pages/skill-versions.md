## 发出去的版本不能再改 {#immutable}

同事按**版本号**安装（例如 v1.2.0）。某个版本一旦审查完成并发布，**包内容与该版本的审查记录不可覆盖**；要改说明或修复问题，只能发布**更高的新版本**。

这样保证：同事检索到的每个版本，都对应当时那份完整的检查记录；不会出现「同一个版本号、内容却被偷偷换掉」的情况。

## 发新版本 {#new-version}

1. 在本地修改 Skill 包，将版本号改为**大于当前最新版**（如从 1.2.0 升到 1.2.1 或 1.3.0）。  
2. 在 {{skill}} 发布页选择已有 Skill（标识不变），上传新包并填写变更说明。  
3. 提交后走同一套三道检查；审查中可在个人中心查看进度。  
4. 新版本通过后，公开检索中会出现新版本；旧版本仍可安装，供尚未升级的同事使用。  
5. 若希望默认安装指向新版本，为新版保留或更新 **`latest` 标签**（见下节）。

> [!TIP]
> 仅修正文案且不影响行为时，仍应发 patch 版本（如 1.2.0 → 1.2.1），以便审查记录与安装记录对齐。

## 标签 {#tags}

**版本标签**指向某个具体版本，用于「默认装哪一条线」：

| 标签 | 常见用途 |
| --- | --- |
| `latest` | 默认最新稳定版；**首个版本必须带此标签** |
| 其他自定义标签 | 如 `beta`、`team-legal`，供特定人群安装试验版 |

同一标签在同一 Skill 上通常只指向一个版本；发新版时可把 `latest` 移到新版本，旧版仍保留历史版本号供精确安装。

## 下架 {#unpublish}

**手动下架**适用于：Skill 已审查通过，但业务上决定不再对外推荐（策略调整、流程废止等）。

| 操作 | 效果 |
| --- | --- |
| 下架整个 Skill 或某一历史版本 | 从公开检索与榜单中隐藏；**已安装的同事本地不受影响**，但新同事一般无法再从广场安装该版本 |
| 重新上架 | 仅对**已通过审查且未被拒绝/中断锁定**的版本；不能把未通过审查的版本直接上架 |
| 删除 / 回收站 | 移入回收站后，在保留期内可恢复；永久删除前请确认无人依赖该标识 |

**审查拒绝**或**审查中断**的 Skill 不能用「重新上架」绕过检查：需修复内容后发新版本，或在中断状态下重试检查。

下架与拒绝的区别：拒绝来自检查结论；下架是作者或管理员主动隐藏已通过的内容。两者都不会自动卸载同事客户端里已存在的副本，需结合内部通知自行收口。
