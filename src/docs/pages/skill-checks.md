## 三道检查 {#checks}

每一份送审都经过**格式**、**质量**、**安全**三道检查，一次完成，列出问题清单。三项结果分开列出；**平台不提供单一的「综合安全分」或「综合质量分」**，避免用一个数字掩盖细节。

检查只读取送审的内容，**不会在你的环境里运行** Skill 包内的脚本。检查在企业自己的机器上进行，**不连外网也能完成**主要静态项；若管理员启用了外网恶意样本比对，未就绪时版本会处于「审查中」，仅作者可见，补齐后自动给出结论。

### 格式检查看什么

确认包结构可被识别、入口说明与元数据完整合法。常见问题：

| 现象 | 典型原因 |
| --- | --- |
| 无法识别入口 | 缺少规范入口文件，或头信息字段不完整 |
| 版本或标识不合法 | 版本号格式错误；标识不符合命名规则 |
| 首个版本无法发布 | 未包含 `latest` 等必需版本标签 |
| 包体或路径不合规 | 体积超限；路径含非法片段 |

### 质量检查看什么

关注**说明是否可执行、可维护**，包括：步骤与边界是否清楚、输出是否可验收、文档是否过长难维护、是否缺少示例或测试描述等。质量维度会以分项问题列出；部分环境还会给出多维对照（如可维护性、规则完整性、护栏与复杂度等），**仍以问题清单为准**，不单看一个总分。

常见问题：摘要未说明使用场景；正文缺少失败时怎么办；说明过于冗长或前后矛盾；仅有口号没有可执行步骤。

### 安全检查看什么

对包内文本与静态资源做**安全扫描**，寻找高风险指令、过宽权限、混淆代码、未声明的外联与敏感信息泄露等。若启用了恶意样本比对，会对包体摘要比对已知威胁；检出恶意类别时会直接触发拒绝。

常见问题：未声明的删除/格式化指令；脚本要求提升权限；大量编码混淆；上传或外传数据的指令未在说明中交代。

> [!NOTE]
> 质量维度的 warn 项通常不会单独导致拒绝，但会使结论变为「需复核」；安全维度的严重项会触发拒绝，详见下节。

## 三种结论 {#verdicts}

审查**全部环节成功结束**后，每个版本会得到以下结论之一：

| 结论 | 意味着什么 |
| --- | --- |
| 通过 | 未留下需阻断的问题；出现在公开检索中，同事可以按版本安装 |
| 需复核 | 存在问题清单，但未命中自动拒绝规则；出现在检索结果中，**带着需复核的标记**，推广前建议人工看过 |
| 拒绝 | 命中高危安全规则或恶意样本判定；**不出现在公开检索中**。问题清单已经列出，处理后可以**发新版本**重新送审 |

**与「审查状态」的区别：**

| 状态 | 含义 |
| --- | --- |
| 审查中 | 仍有环节在等待外部结果（如样本比对排队）；**不是失败**，作者可在个人中心查看，公众不可见 |
| 审查中断 | 某环节因环境或超时未完成；包通常已暂存，修复后可**重试检查**，一般无需重新上传同版本 |
| 审查完成 | 流水线已跑完，此时才对应上表的通过 / 需复核 / 拒绝 |

## 结论留档 {#records}

每一次检查的问题清单、各道检查的结果与最终结论都会**按版本保留**，之后随时可以回看。Skill 详情页的「审查与评估」区域可查看历史版本的记录；组织内也可在审查中心横向对比多个 Skill 的最新结果。

改进 Skill 后应**发布新版本**，新结论归属新版本；已发出去的旧版本记录不会被覆盖，同事安装的仍是他们当时选择的版本号。
