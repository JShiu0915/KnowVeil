## 存、取、用、鉴 {#loop}

两个产品接成一个循环：

| 环节 | 做什么 | 由谁完成 |
| --- | --- | --- |
| 存 | 把知识整理进企业自己的目录 | {{knode}} |
| 取 | AI 按需读取它该读的那一部分 | {{knode}} |
| 用 | 在你选的那款 AI 里完成推理和回答 | 你选的 AI |
| 鉴 | 把验证过的做法做成能力，检查过再发给全组织 | {{skill}} |

用得越多，知识越厚；知识越厚，AI 越好用。

## 知识放在 {{knode}} {#knowledge}

知识集中放在企业自己的电脑或服务器上，由人来维护，AI 直接使用。AI 引用某段内容时，出处精确到原文的哪一节。

**一个完整例子（合同审查）：**

1. 法务部在 {{knode}} 里维护「合同审查要点」「常见条款说明」等项目文档。
2. 业务同事在 Claude、Cursor 等客户端里提问：「这份采购合同里，付款条款有哪些风险点？」
3. AI 通过 {{knode}} 读取相关章节后回答，并在回答里标出引用了哪几篇文档、哪一节。
4. 同事点开出处，对照原文确认；若原文有误，直接在 {{knode}} 里改，下一次提问用的就是新内容。

> [!TIP]
> {{knode}} 不替 AI 做推理，只提供知识读写与出处；模型仍由你选的客户端或企业自部署环境提供。

## 能力交给 {{skill}} {#capabilities}

在 {{knode}} 里反复用过、验证过的做法，可以整理成 Skill 送审。检查通过后，同事能在组织内的公开检索里找到它，按版本安装到各自的 AI 客户端。

**什么时候值得做成 Skill？**

| 适合做成 Skill | 继续放在 {{knode}} 里即可 |
| --- | --- |
| 多人都要用同一套步骤（如合同审查清单、经营日报模板） | 只服务单个项目、还在频繁改动的草稿 |
| 步骤相对固定，需要统一版本与审查记录 | 一次性资料、背景说明 |
| 希望新同事「安装即用」，而不是每次重新口述流程 | 含大量个案细节、不宜打包成通用能力 |

**同一个部门的例子：** 法务部在 {{knode}} 里沉淀了审查要点后，把「按清单逐条核对 + 输出结论表」的做法打成 Skill「合同审查助手」，送审通过后，其他部门安装的始终是同一套经过检查的版本；要点文档仍在 {{knode}} 里继续增厚，Skill 发新版本时再同步调整。

| 问题 | 找谁 |
| --- | --- |
| 知识放哪、怎么分层、怎么备份分享 | {{knode}} |
| 哪一款 AI 能读这份知识 | {{knode}} + [接入常用的 AI 客户端](/docs/clients) |
| 能力能不能发给全组织、检查结论是什么 | {{skill}} |
| 发出去的版本能不能改、怎么下架 | {{skill}}，见[版本、标签与下架](/docs/skill-versions) |
