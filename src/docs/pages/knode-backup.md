## 整包带走 {#take-it-all}

知识就在企业自己的电脑或服务器里，以可读文档形式存放，**随时能整包带走**：复制整个知识库目录即可完成物理备份，不依赖导出向导或厂商云端。

每一篇文档的变更都有版本记录，便于对比与回溯。这与「数据留在企业自己的机器上」的承诺一致：迁机、断网、更换 AI 供应商，底账始终在你手里。

## 备份 {#backup}

例行备份与恢复演练由 **{{brand}} 团队**按交付策略执行。企业若合规上需要自留副本，知识库仍是本地目录，可在约定窗口内**整包复制**带走，不依赖导出向导。

| 方式 | 说明 |
| --- | --- |
| 团队例行备份 | 默认方式；频率与保留周期在交付说明中约定 |
| 企业自留副本 | 复制整个知识库根目录即可；重大批量导入前可联系 {{brand}} 团队做快照 |
| 可选云同步 | 若方案中启用，数据在你方云账号下；与 {{brand}} 在实施阶段约定 |

## 搬到新环境 {#migrate}

迁机、换服务器或扩容由 **{{brand}} 团队**组织实施：复制知识库、切换服务指向、更新交付给各客户端的 MCP 配置，并在维护窗口后抽样验证索引与引用。

企业侧只需在约定时间配合短暂只读或停写；**无需自行安装或重装 {{knode}}**。若有合规审计，可在迁移前后各做一次自留副本（见上节）。

## 分享其中一部分 {#share}

有时只需把**某个项目**（含其文档与子结构）交给外部顾问、分公司或合作伙伴，而不是导出全库。

{{knode}} 支持将选定项目打成**加密分享包**：

| 要点 | 说明 |
| --- | --- |
| 范围 | 通常按项目打包；可选带上该项目引用的外部文档快照，避免对方缺上下文 |
| 安全 | 包体加密；解密所需信息由企业自行保管，不在公网明文传播 |
| 接收方 | 在自有 {{knode}} 实例中导入，与本地知识库合并或单独目录存放（按导入向导） |
| 审计 |  manifest 中记录导出时间、项目名称等元数据，便于留痕 |

**不宜分享的内容**请先在内网做脱敏；分享包解决的是「可控地给出一截知识」，不能替代企业整体的访问控制策略。

> [!WARNING]
> 更换分享加密配置后，旧分享包可能无法解密；变更前应与接收方协调，并保留未轮换前的备份。
