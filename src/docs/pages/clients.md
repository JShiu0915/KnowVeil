## 可以接入的客户端 {#supported}

下面这些 AI 客户端可以直接接入 {{knode}}，以及**任何支持 MCP 的 AI 客户端**：

Claude、Codex、Cursor、CodeBuddy、Cline、Kilo Code、OpenCode、Cherry Studio、OpenClaw、Hermes Agent、MiMo Code、Qwen Code。

换工具，不用迁移知识。知识仍留在 {{knode}} 的本地底账里，只是换一款客户端通过 MCP 读取同一份内容。

> [!NOTE]
> {{knode}} 本身不包含大语言模型；推理与对话发生在所选客户端或企业自部署的模型侧。{{knode}} 的服务端安装与运维由 {{brand}} 负责；同事只需在**自己的 AI 客户端**里完成下面几步。

## 接入步骤 {#steps}

以下以 **Cursor** 为例；其他客户端只需找到各自的「MCP 服务器 / 工具」配置位置，填入同一份连接信息即可。

1. **确认环境已开通**  
   {{brand}} 交付并完成 {{knode}} 初始化后，会向贵方提供 MCP 连接配置（或写入使用说明）。写操作所需的作者身份，通常已在开通时登记。

2. **复制 MCP 连接配置**  
   使用交付材料中的 JSON 配置块。**以实际提供的内容为准**，不要手工猜测命令路径。

3. **写入客户端**  
   - Cursor：打开 MCP 设置，新增服务器，粘贴或合并上一步的配置。  
   - CodeBuddy、Cline 等：在对应配置文件中增加同名 MCP 服务器块（路径因客户端而异，见客户端官方说明）。

4. **重启客户端**  
   保存配置后完全退出并重新打开客户端，使 MCP 连接生效。

5. **验证**  
   在对话中让 AI「读取知识库索引」或「列出当前有哪些项目」。若能返回 {{knode}} 里的项目名称或摘要，说明接入成功。  
   再提一个与已有文档相关的问题，检查回答是否带有可点回的出处（见 [引用的出处怎么核对](/docs/knode-citations)）。

**业务同事不用配 MCP 时：** 可直接用浏览器打开 {{knode}} 的 Web 界面查阅与编辑；与 AI 使用的是同一批文档。

> [!WARNING]
> 若连接失败，先核对配置是否与交付材料一致；仍无法连接时，联系 {{brand}} 团队排查服务端与网络，并确认本机安全软件未拦截客户端。

## 企业自己部署的 AI {#self-hosted}

企业在内网部署的模型与 Agent 平台，只要支持 MCP，接入方式与上节相同：把 {{knode}} 的 MCP 配置登记到该平台的工具列表中即可。

**接入前宜与 {{brand}} 及贵方网络管理员确认**（仅涉及连通与策略，不要求企业自行部署 {{knode}}）：

| 项 | 目的 |
| --- | --- |
| 客户端或 Agent 网关能访问 {{knode}} MCP 所在主机与端口 | 网络可达 |
| 是否允许 AI 写知识 | 按企业策略；{{knode}} 对写操作有受控入口，AI 不能随意直改文件 |
| 日志与审计要求 | 结合 {{knode}} 的版本记录与客户端侧会话留存，满足内控需要 |

自托管模型换版本或换供应商时，**不必迁移知识库**，只需在新客户端上重新登记同一份 MCP 配置。
