## 按项目与主题分层 {#layers}

知识库从**根目录**开始，向下分为「公共知识」与「项目」两类节点；**项目可以嵌套子项目**，结构在每一层重复，便于按业务线或课题归档。

| 位置 | 放什么 |
| --- | --- |
| 库级公共知识 | 全组织共用的制度、术语、模板说明 |
| 项目 | 一个课题、一条产品线或一次专项的全部材料 |
| 项目下的公共知识 | 仅属于该项目的文档条目 |
| 子项目 | 大项目下的分课题（结构同项目） |
| 归档 | 已结束、取消或废弃的项目与子项，移入归档区，仍可查阅 |

每一层都有**索引页**，列出本层的文档摘要、子项目与归档入口。打开索引就知道东西放在哪、哪一块还空着；AI 也从索引起步，逐层下钻到相关文档，而不是在一盘散沙里盲搜。

**推荐的分层方式：**

1. **按组织职责分项目**（如「法务合规」「华东区运营」），跨部门共用内容放库级公共知识。  
2. **单项目文档不宜过长**：一篇文档一个主题，便于出处精确到节。  
3. **结项即归档**：状态改为已完成/取消/废弃后，整项移入 `archive`，活跃索引里只保留在办内容。  
4. **用摘要字段说清用途**：索引与列表里显示的一句话摘要，决定同事和 AI 会不会点进去。

**简化示例（仅示层级，名称请按企业实际命名）：**

```text
知识库根索引
├── 公共知识/
│   ├── 术语表.md
│   └── 采购管理制度摘要.md
└── 项目/
    └── 合同审查/
        ├── 索引（本项目说明与文档列表）
        ├── 公共知识/
        │   ├── 审查清单.md
        │   └── 常见条款说明.md
        └── 子项目/
            └── 2026-供应商模板/
                └── 公共知识/…
```

库级还有**项目状态一览**，方便一眼看到哪些项目在办、哪些已归档。

## 由人来维护 {#people}

知识由人来维护，AI 直接使用。谁在什么时候改了什么，都有版本记录，可以回溯。

- **写操作需要身份**：创建或修改文档前会登记作者，便于审计。  
- **AI 走受控入口**：AI 不能直接任意改动磁盘上的文件，只能经 {{knode}} 提供的读写入口操作。  
- **索引随内容更新**：文档增删改后，上层索引会同步刷新，避免人手维护目录表。

业务同事可在 Web 界面编辑；技术人员可在 AI 客户端里协作维护，两者读写同一批文档。

## 建第一个项目 {#first-project}

1. **开通知识库**（由 {{brand}} 团队在交付时完成）：创建空库并通过自检。  
2. **设置身份**：登记邮箱与显示名称，供后续写操作记录作者（开通时或首次登录时完成）。  
3. **在根索引下新建项目**：命名尽量稳定（文件夹名即项目标识），填写一句话摘要与状态「进行中」。  
4. **在项目下创建第一篇文档**：例如「背景与范围」，写清本项目知识包含什么、不包含什么。  
5. **打开项目索引确认**：应能看到刚创建的文档出现在列表中；若使用 Web，可在阅读态预览目录树。  
6. **（可选）配置 MCP**：让 AI 客户端连接 {{knode}}，在对话中验证 AI 能列出该项目并读取文档。

> [!TIP]
> 先建一个小项目试点（十篇以内文档），跑通「写入 → AI 引用 → 出处核对 → 修改」再推广到更多部门。
