## 装在哪里 {#where}

{{brand}} 的两个产品都部署在**企业自己的环境**里：知识底账与 Skill 注册表的数据留在组织内，不依赖公有云托管你的内容。

**安装、升级与日常运维由 {{brand}} 团队负责**，企业无需自行组建信息部门来部署本产品。交付时会与贵方确认网络与访问方式；环境评估、装在哪台机器、如何备份，由 {{brand}} 团队在实施阶段一并落实。

| 产品 | 典型部署位置 | 说明 |
| --- | --- | --- |
| {{knode}} | 员工电脑、部门文件服务器，或内网应用服务器 | 知识以可读可带的本地目录形式存放；需要 Web 编辑时，在同一台或内网服务器上启用浏览器访问即可 |
| {{skill}} | 内网应用服务器 | 提供 Skill 发布、检索、检查与下载；可独立域名访问，也可嵌入现有内网门户的子路径 |

**运行环境（由 {{brand}} 团队验证）：**

- {{knode}}：支持 Windows、macOS、Linux；安装完成后可用内置自检确认就绪。
- {{skill}}：注册表与制品存储部署在企业内；检查流水线在本地运行，**不连外网也能完成**格式、质量与安全相关的静态检查（是否启用可选的外网恶意样本比对，在交付时与贵方约定）。

> [!NOTE]
> 本文说明**数据落点与分工**，便于业务负责人对齐预期。具体实施计划、变更窗口与联系人，以与 {{brand}} 签订的交付说明为准。

## 谁来维护 {#who}

| 角色 | {{knode}} | {{skill}} |
| --- | --- | --- |
| **业务部门** | 维护项目与文档内容；确认 AI 引用是否准确 | 编写 Skill 说明与包内容；根据检查清单修改后重新送审 |
| **{{brand}} 团队** | 部署与升级、健康巡检、备份与恢复、MCP 接入协助；按约定配置分享与同步策略 | 部署与升级、注册表与制品备份、检查服务可用性、账号与 API 访问支持 |
| **贵方合规 / 安全** | 确认知识不出域、留存与审计要求 | 复核「需复核」结论；关注安全类问题清单 |

业务人员可以只通过浏览器使用 {{knode}} 的 Web 界面录入与查阅；技术人员通过 MCP 与 AI 协作维护同一份知识，无需两套内容。

## 日常要照看什么 {#routine}

**由 {{brand}} 团队例行完成**（企业侧一般无需安排专职运维）：

| 事项 | 说明 |
| --- | --- |
| 健康巡检与升级 | 环境自检、补丁与版本升级、变更后验证 MCP 与 Web |
| 备份与恢复 | 知识库与 Skill 注册表按交付策略备份；恢复演练按约定进行 |
| 容量与检查服务 | 磁盘与制品增长、静态检查组件可用；审查「中断」时由 {{brand}} 团队修复环境并重试 |

**建议企业侧关注**（与内容和使用相关）：

| 事项 | 说明 |
| --- | --- |
| 知识质量 | 文档是否及时更新、出处是否仍准确；见 [知识目录怎么组织](/docs/knode-directory) |
| Skill 送审 | 发布前自查；对「需复核」结论安排业务或合规确认 |
| 新员工 | 开通浏览器或 MCP 接入（可由 {{brand}} 团队代办配置）；阅读路径见[概览](/docs#reading-order) |

> [!TIP]
> 新同事入职：向 {{brand}} 团队或内部管理员索取 {{knode}} 访问方式与 MCP 配置，即可在 [接入常用的 AI 客户端](/docs/clients) 一节对照完成客户端侧设置。
